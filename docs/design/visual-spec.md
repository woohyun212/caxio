## 2. 픽셀 격자와 무대

가용 CSS 뷰포트에서 k=min(floor(W/416),floor(H/250)). k≥2면 와이드. 프레임은 정확히 416k×250k, 좌상단은 남는 폭·높이의 절반을 각각 내림한다. 밖은 ink. 상태 띠 16 → 장면 196 → 메시지 16 → 명령 22. 장면 내부 y=0..29 받침, 30..45 명판, 46..143 테이블, 144..195 손패. 리사이즈 시 렌더 타깃은 고정하고 출력 버퍼·DOM 배율만 갱신한다. DPR은 k 계산에 넣지 않는다. 확대/축소 시 CSS 뷰포트를 다시 재고 선택 ID와 포커스 ID를 복원한다.

와이드의 R3F Canvas는 dpr=1, flat, alpha=false, antialias=false, demand. 416×196 RGBA8 WebGLRenderTarget, NoColorSpace, min/mag NearestFilter, mipmaps/MSAA 없음. 타깃에는 표시 sRGB 바이트를 바로 기록. 흰색 기본 MeshBasicMaterial 아틀라스, alphaTest=0.5, 커버리지 ShaderMaterial, 별도 씬 전체화면 복사 ShaderMaterial만 사용한다. 팔레트는 TS 바이트/255에서 가져온다. 색 변환·톤 매핑·조명 재질·그림자 맵·블렌딩·후처리 패키지가 개입하지 않는다. 복사 좌표는 ivec2(gl_FragCoord.xy)/k, texelFetch(level 0). 마지막 칸까지 정확히 k×k. WebGL 기본 DITHER를 끈다. Canvas 자체만 image-rendering: pixelated, k×DPR이 비정수일 때 transform: translate(0.015625px,0.015625px), 정수면 none. 박스·카메라·DOM hit 좌표는 이동시키지 않는다. 물리 픽셀 중심을 역투영해 경계 동률은 좌·상에 귀속한다. 분수에서는 칸 폭이 floor/ceil(k×DPR)로 달라져도 혼합 블록과 기준 오차는 0이어야 한다. 언마운트 때 target·geometry·material·texture를 해제한다.

**공통 배치.** 화면 좌상단 원점, x 오른쪽, y 아래. 탁자 구역 (0,46,416,98). 상면은 중심 (208,98), 투영 반높이 44, 양쪽 반원 중심 간격 300인 스타디움이다. 가장자리에서 안으로 ink 1, paper 1, sage 3, 속은 펠트. 중앙 캡션 (130,59,156,16), 바닥 타일 y=83. 긴 조합명은 캡션을 중앙 정렬한 펠트 폭 안에서 확장한다. 손패 y=151, 선택 y=146. n장 폭 30n−2, x=floor((416−폭)/2)+30i. 13장 388, 12장 358, 중앙 5장 148. 구름<별<달<해, 숫자 3..N,1,2 순. 비운 슬롯은 즉시 중앙 정렬한 목표로 옮긴다.

시작 seatOrder에서 나 다음부터 왼쪽→오른쪽으로 n=2/3/4열. 열 폭=floor(416/n), 좌우 여백=floor((416−열 폭×n)/2), 중심=왼쪽 여백+(i+0.5)×열 폭. 내 좌석이 탈락해도 재배치하지 않는다. y=1의 등판은 폭 20×26, 중심 기준 20+6(r−1) 폭에 r장. r=0이면 비운다. 13장 92px, 12장 86px. 명판은 y=30, 높이 16, 좌우 4px 안쪽에 ‘N번 R장 C칩’(실측 최대 92px, 104px 열의 내부 폭 96px), 차례 때 반전. 받침 위 상태 라벨은 해당 등판 상단에 붙이고 명판은 가리지 않는다. 탈락 > 끊김 > 패스 순으로 표시, 차례는 독립 표기. 좌석별 연결 상태는 DOM 이름에도 포함한다. 칩은 실잔액 정수와 ‘칩’ 단위로 표기한다.

**채택 무대 B.** 수평면에서 55° 올린 고정 직교 카메라. 좌우 경계 ±208, 상하 ±98, near=0.1, far=1600, 위치 (0,600 sin55°,600 cos55°), 원점을 본다. 탁자 상면의 깊이 방향 반지름=44/sin55°, extrusion 깊이 9, bevel 없음, curveSegments=10. 받침은 92×7×12 박스, 중심은 (열 중심,26)에 투영한다. 5인 x=52/156/260/364. 등판은 20×30×2 박스, X 회전 −0.42rad, sage 면과 ink 테두리만. 테이블·받침 옆벽은 c=clamp(0.45+0.35·dot(월드 단위 법선,normalize(−0.4,0.7,1)),0,1)로 ink/pine을 교대한다. 앞면은 camera.quaternion을 복사하고 정수 목표 슬롯을 월드로 역투영해 1 texel=1 논리 px를 유지한다. 카메라 이동·회전·줌은 없다.

**A · 전환 시 차이.** Q1의 비교 무대는 정면 직교, 화면 1px당 월드 1단위, 평면 스타디움과 평면 받침이다. 같은 손패·캡션·슬롯을 공유하며 상대 등판에 20×26 아틀라스의 C와 체커를 1:1로 쓴다. 출시 구현은 위의 B 한 경로를 사용한다.

t=(matrix[y mod 4][x mod 4]+0.5)/16. 밝은 면 비율 c>t면 밝은 바이트, 아니면 어두운 바이트다. 펠트는 ink/pine, 안쪽 경계까지 거리 d가 [0,12), [12,28), [28,∞)이면 각각 c=2/16,5/16,8/16. 바닥의 접지는 발자국 안 pine, 바깥 1px는 pine/sage 8/16. 펠트의 접지는 안쪽 c=0, 바깥 1px는 원래 c/2. DOM 버튼의 히트 사각형은 목표 슬롯의 원위치다. 포커스만 실제 보이는 면 둘레에 바깥 ink 2px, 안쪽 paper 1px로 그린다. Tab/Shift+Tab으로 상태 버튼→손패 약한 순→제출→패스, Enter/Space로 토글·승인 요청. 메뉴는 일반 버튼으로 열고 Escape로 닫아 호출 버튼에 포커스를 돌린다. 타일 제거 시 다음 남은 슬롯, 없으면 차례 상태 제목으로 포커스 이동. 키보드·스크린리더에는 모든 카드와 조합을 ‘문양 숫자’ 텍스트로 제공한다.

상대 차례에 미리 선택 가능. 공유 classify/compare가 선택 전체에 판정하고 선택 0장 ‘패를 골라 주세요’, 장수 오류 ‘1·2·3·5장만 낼 수 있어요’, 족보 오류 ‘조합이 아니에요’, 바닥 장수 불일치 ‘같은 장수로 내세요’, 비교 실패 ‘바닥보다 높은 조합이 필요해요’를 쓴다. 합법·내 차례·현재 기한 안에서만 ‘제출 N장’ 활성. 패스는 내 팔로우 턴에만 활성. ‘선은 패스할 수 없어요’, ‘내 차례를 기다려 주세요’, ‘서버 응답 대기’, ‘시간이 지났어요’, ‘연결이 끊겼어요’로 상태를 전한다. 장애 > 최신 일시 통지(거절·자동 처리·배분) > 상시 사유 순, 일시 통지는 다음 사용자 입력 또는 차례 변경까지. 상시 사유 우선순위는 대기→만료→남의 차례→선택 오류→선 패스 불가. 비활성 버튼에도 사유를 aria-describedby로 연결한다.

응답 전 손패·칩·차례를 낙관적으로 고치지 않는다. 중복 PLAY/PASS와 선택 변경을 막고, 거절 시 최신 스냅샷의 보유 타일과 교집합인 선택을 복원한다. 서버 기준 남은 시간은 수신 시 performance.now()를 기준점으로 ceil(max(0,deadline−serverNow−경과ms)/1000). 네트워크 전달 지연만큼 표시 오차가 가능하다. ±30초 로컬 벽시계 차이와 무관. ≤5초는 반전과 ‘마감 N초’, 0이면 ‘0초 · 처리 중’, 서버만 만료 처리. 자동 리드는 최저 싱글, 자동 팔로우는 패스. 차례 변경·거절·정산은 단일 aria-live=polite, 초는 낭독하지 않는다.

## 4. 화면별 와이어프레임과 컴포넌트

와이드 1280×800에서는 k=3, 프레임 1248×750이다. 아래 표에서 ‘/’는 다음 행, ‘+’는 같은 행, 대괄호는 조작 가능한 요소다. 대국의 공통 와이어는 두 가지다. 각 상태 행은 해당 공통 와이어의 칸을 채우거나 교체한다.

```text
1280×800                          360×640 (Canvas 없음)
상태: caxio | 차례·선/받기 | 초·예고 | R | 소리·메뉴    caxio·차례 + [소리][메뉴] / 초·자동 예고·R
받침: 상대 등판 더미 × (2..4)                        상대 좌석 × (2..4) / 장수·칩·상태
명판: 번호·장수·칩 / 위에 패스·끊김·탈락               중앙 캡션 / 현 조합 또는 직전 기록·패널
펠트: 중앙 캡션 / 현 조합 또는 직전 기록·패널          내 손패 7+6
손패: 내 패 한 줄                                   메시지
메시지                                              선택 / 나·칩 + [제출 N장] [패스]
나·칩 + 선택 요약 + [제출 N장] [패스]
```

와이드 상태 띠의 워드마크/차례/초와 예고/R/소리/메뉴의 (x,폭)은 (1,40)/(42,99)/(142,139)/(282,42)/(325,43)/(370,44). 마감 문구와 초과 예고가 길면 R칸까지 시간을 확장하고 R은 워드마크 자리로 옮긴다. 명령 행의 나/선택/제출/패스 칸은 (2,97)/(100,140)/(243,101)/(346,68). k=2일 때 16px 띠가 32 CSS px이므로, 두 버튼의 히트 높이는 다음 행의 오른쪽 여백으로 12 CSS px 연장한다(상대 받침은 무입력). 컴팩트에서는 버튼을 44 CSS px 이상으로 별도 두고 초·예고와 충돌하면 차례·R과 예고를 두 줄로 만든다. 손패·중앙 타일 사이 CSS 틈 2. 7장 폭은 348, 5장 폭은 248. 줄을 가운데 정렬한다. 360px 미만의 확대 뷰포트에서는 한 줄 열 수=min(7,max(1,floor((폭+2)/50)))로 줄이고 필요하면 세로 스크롤로 접근한다. 폭이 648 이상이면 13장을 한 줄, 아니면 최대 7열, 각 48×80 CSS px. 선택 상단 여백 10px, 행 피치 90px. 소리·메뉴와 별도로 폰의 제출·패스 폭은 최소 60 CSS px. 세 자리 내 칩 값이 길면 ‘나 1번 320칩’처럼 장식 구분점을 생략한다. 360·390·430 세로는 7+6, 768×1024와 844×390은 한 줄. 패가 줄어도 명령행의 순서와 폭을 유지한다.

Q3 합성 실측에서 세로 5인은 상태 68(44+24), 좌석 96, 캡션 24, 중앙 80, 손패 180, 메시지 24, 선택 24, 행동 44 = 540 CSS px. 상태 첫 줄은 caxio+차례+[소리][메뉴], 둘째는 초·자동 예고+R. 마지막 행은 내 칩+[제출][패스]. 4인은 좌석 72로 516px. 844×390 가로는 44+24+24+80+90+24+0+44=330px, 명령 행에 내 칩·선택·행동이 함께 있다. 648~759px 폭에서 한 줄 상태 문구가 넘치면 상태만 68px 두 줄로 둔다. 긴 오류나 족보는 줄을 늘릴 수 있지만 기본 상태의 행은 고정한다. 소형 화면 장문에는 같은 의미의 짧은 문구(예: ‘마감 5초 · 최저 1장 자동’)를 쓰고 전체 문장을 접근 가능한 이름으로 유지한다. 아래 지원 크기에서 손패·차례·버튼이 한 화면에 들어가는지 출시 때 다시 잰다.

중앙 대표값은 싱글 그 패, 페어 최고 문양, 트리플·풀하우스·포카드 본체 숫자, 스트레이트·플러시·스트레이트 플러시 최고 numRank 패다(1-2-3-4-5는 2). ‘패스’와 ‘새 선’은 통지로도 읽힌다. 초과 처리는 서버 승인 후 ‘시간 초과로 최저 싱글을 냈어요’ 또는 ‘시간 초과로 패스했어요’. 이미 보았던 lastAction은 presence 변경·복귀 첫 스냅샷에서 재공지하지 않는다. 현재 클라이언트 요청과 턴 전이가 경합하면 서버가 표시한 처리 종류를 우선한다.

정산은 제목·순위·내 줄을 펠트 안에 놓는다. 각 행은 ‘1위 1번 +3칩 → 67칩’. E=0/1/2인 3석의 실제 증감은 +3/0/−3, 잔액 67/64/61. 지급 도중 0이면 실제 지급액까지만 반영하고 이후 수금은 0. ‘남은 3장 × 4배(2가 2장) = 12’는 수신자 전용 데이터에서만 조판한다. 공개 순위와 증감에서 개인 간 송금액을 추정해 애니메이션하지 않는다. 이전 잔액→확정 잔액과 부호로 칩 이동을 읽는다. 다음 판이 있으면 ‘탈락 · 다음 판 관전’, 끝나면 ‘탈락’. 다섯 줄+본인 내역이 넘칠 때 [이전][다음]으로 펠트 안에서 페이지를 바꾼다. 정산은 도착 즉시 열고 다음 라운드 최초 PLAY 승인에서 접는다. 메뉴의 [직전 정산]으로 다시 연다. 배경을 가리거나 초점을 가두지 않는다.

메뉴 [족보]는 같은 패널에 3쪽으로 표시한다. ① 숫자 3..N<1<2, 구름<별<달<해, 1·2·3·5장 ② 스트레이트<플러시<풀하우스<포카드<스트레이트 플러시, 플러시는 숫자 먼저 ③ 일반 3..7부터 (N−4)..N, 특수 1·2·3·4·5, 2·3·4·5·6, (N−3)..N 다음 1 허용, (N−2)..N 다음 1·2 금지, 남은 장수×2^(남은 2의 수). 패널을 닫지 않고 선택·제출할 수 있다.

### 장면 실패와 소리

WebGL2 사전검사 실패, 렌더러 생성 예외, contextlost, import 거절은 테이블 경계에서 각각 처리한다. 화면 전체를 초기화하지 않고 CANVAS를 치운 뒤 같은 DOM 슬롯을 불투명하게 그린다. ‘그래픽을 사용할 수 없어 기본 화면으로 진행해요’는 장면 안의 정적 설명이다. 손패·바닥 DOM 이미지는 최초 프레임 표시가 완료된 뒤에만 숨기고 버튼과 텍스트 대안은 유지한다. 컴팩트에 바로 입장하면 Three/R3F 청크 요청 0회. 와이드에서는 로비 입장 뒤 장면만 미리 받는다. 음향 모듈은 장면과 별도 진입점이며 DOM 전용에서도 동작한다.

위치 damp는 초 단위 delta에서 x'=goal+(x−goal)exp(−λdelta). 선택 λ=25/s(95% 약 120ms), 제출·배분·재정렬 λ=14/s(약 214ms). 연속 위치를 유지하다 투영 후 반올림한다. 모든 축 오차 <0.001이면 목표에 붙이고 invalidate 중단. 상대 PLAY는 해당 받침에서 같은 프레임에 등판이 줄고 앞면이 중앙으로 이동한다. 내 PLAY는 이전 슬롯에서 출발. 배분은 중앙에서 각 슬롯으로, 계산 중 클릭은 목표 슬롯의 패를 고른다. 이전 바닥 패 제거·패스 라벨·칩 잔액·패널·턴은 즉시 교체한다. reduced-motion은 다음 프레임에 모두 목표 도착. 카메라, 글리프 크기, 밝기를 보간하지 않는다.

| --- | --- | --- |
| 승인 PLAY | 삼각파 480→220Hz 선형 하강, 45ms. Gain 0→0.10(3ms 선형)→0(45ms 선형), 끝에서 stop. | lastPlay.turnId당 1회. 마지막 제출이면 정산 구절에 앞선다. |

첫 사용자 제스처에서 AudioContext를 생성·resume, 소리 기본 켬. 상태 띠 ‘소리/무음’ 토글 aria-pressed는 음소거 여부를 나타낸다. sessionStorage의 caxio.muted는 탭 수명, 방 자격과 독립. 무음·차단 상태의 사건은 소급 재생하지 않는다.

**출시 전 증거.** Bun으로 Bayer 순서/16단계 점유, CPU 색, fitScale 표, 앵커·슬롯, snap, damp(30/60/120Hz의 0.5초 차이 ≤0.001), 60면·좌석 이름·대표값·메시지 우선순위·파일 검사를 Bun만으로 반복한다. 실제 렌더 타깃 픽셀 vs CPU 기대값 차이 0, 모든 재질의 8견본 RGB 일치, k×k 혼합 블록 0. 정지 2초 추가 렌더 0, 두 정지 캡처 차이 0. 한 타일 이동 차이는 전후 경계·그림자 안에만 존재. 5인 최대 장면(48등판+12손패+5바닥) M3 Chrome DPR1, k=3에서 20프레임 예열·120프레임 정상·60프레임 동기 읽기를 3회 측정하고 세 중앙값의 중앙값으로 CPU 제출 ≤1ms, 동기 readback 포함 중앙값 ≤5ms, draw calls ≤150. 휴대폰 한 대에서 실측 환경·값을 기록한다.

제품 프레임은 로비·12/13장·5장 바닥·상대 차례·불법 선택·마감 5초·정산·관전·종료·컴팩트를 캡처한다. 위 여섯 필수 뷰포트에서 스크롤·겹침 0, DPR 2 및 리사이즈 전후 경계 1px 안 클릭 적중·2px 틈 미적중. WebGL 실패 네 종류에서 수동 PLAY와 PASS의 서버 승인·동일 선택을 각각 기록한다. 200% 확대·키보드만으로 한 턴. 1배 시트와 정수 확대, 적색맹·녹색맹·청색맹·회색조에서 문양과 6/8/9/0,1/7,3/8,10/18 혼동을 확인한다. 소유자가 손패·직전 제출·차례·초·좌석별 장수와 칩을 읽은 결과, 스피커로 들은 결과를 SHA와 함께 별도 기록한다. 생성 이미지는 판독 시험에 쓰지 않는다.

기존 스파이크의 관측 범위는 M3 Chrome DPR1, 1280×800·1103×719, WebGL 사전 검사 실패다. 그 스파이크는 다른 해상도와 양자화 경로를 사용했다. 제품 Safari·Firefox·분수 DPR·실기기 터치·보조기기·가청 출력·GPU 성능은 제품 빌드에서 확인한다.
