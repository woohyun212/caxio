# 온라인 렉시오 최종 시스템 명세

온라인 렉시오 개발에 바로 적용할 수 있도록 공식 규칙 + 확정된 정책(공식 탈락제 파산 처리, 타임아웃 자동 처리)을 하나로 통합한 최종 시스템 명세입니다.

## 1. 게임 기본 구성 및 데이터 모델

모든 타일은 `(number, suit)` 고유 쌍으로 정의하며, 비교 연산 오류를 막기 위해 표시 숫자(`number`)와 강도 서열(`numRank`)을 분리합니다.

* **문양 서열 (`suitRank`)**: `구름(0) < 별(1) < 달(2) < 해(3)`
* **숫자 서열 (`numRank`)**: 현재 라운드 최대 숫자를 $N$이라 할 때 `3`이 최약, `1`이 차상위, `2`가 최강입니다.
  * `3..N` $\rightarrow$ `0..(N-3)`
  * `1` $\rightarrow$ `N-2`
  * `2` $\rightarrow$ `N-1`
* **초기 세팅**: 인원 무관 1인당 **64점**(1점×4, 5점×4, 10점×4), 기본 **5라운드** 진행([디다노니아 공식 가이드](https://www.didanonia.com/lexio)).

| 생존 인원 ($M$) | 사용 숫자 ($1 \sim N$) | 총 타일 수 | 1인당 배분 | 비고 |
| --- | --- | --- | --- | --- |
| 5인 | 1 ~ 15 | 60장 | 12장 | 전체 사용 |
| 4인 | 1 ~ 13 | 52장 | 13장 | 14, 15 제외 |
| 3인 | 1 ~ 9 | 36장 | 12장 | 10~15 제외 |
| 2인 (옵션) | 1 ~ 9 | 36장 중 24장 | 12장 | 12장 비공개 제외 |

## 2. 족보(조합) 판정 및 비교 로직

제출 가능한 장수는 **`1`, `2`, `3`, `5`장**뿐이며(4장 단독 불가), 테이블에 직전 조합(`tableHand`)이 있을 때는 **반드시 같은 장수**이면서 비교 키가 더 큰 조합만 허용합니다.

* **싱글 (1장)**: `(numRank, suitRank)` 비교.
* **페어 (2장, 동일 숫자 2장)**: `(numRank, max(suitRank))` 비교(4문양이 유일하므로 무승부 불가).
* **트리플 (3장, 동일 숫자 3장)**: `(numRank)` 비교.
* **메이드 (5장)**: `madeTier` 서열 `스트레이트(0) < 플러시(1) < 풀하우스(2) < 포카드(3) < 스트레이트 플러시(4)`를 최우선 비교하고, 동등급일 때만 아래 비교 키를 순차 비교합니다.

| 5장 족보 | 성립 조건 | 동등급 비교 키 (Tuple 순차 비교) |
| --- | --- | --- |
| **스트레이트** | 허용된 연속 숫자 5개 | `(최고 numRank, 차순위 numRank, 최고 numRank 타일의 suitRank)` |
| **플러시** | 같은 문양 5장 | `(내림차순 정렬된 5개 numRank 전체, suitRank)` |
| **풀하우스** | 트리플(3장) + 페어(2장) | `(트리플의 numRank)` |
| **포카드** | 같은 숫자 4장 + 임의 타일 1장 | `(포카드 4장의 numRank)` |
| **스트레이트 플러시** | 스트레이트 + 플러시 동시 충족 | 스트레이트와 동일 (`숫자 조합 우선 → suitRank`) |

**족보 판정 시 필수 예외 처리 3가지**

1. **스트레이트 유효 집합 ([공식 FAQ](https://lexio.co.kr/bbs/board.php?bo_table=0111&wr_id=64))**:
   * 일반 연속(`3-4-5-6-7`, …, `(N-4)~N`)과 특수 연속(`1-2-3-4-5`, `2-3-4-5-6`, `(N-3)-(N-2)-(N-1)-N-1`)만 인정합니다.
   * `(N-2)-(N-1)-N-1-2`(예: `13-14-15-1-2`) 형태는 **무효**입니다.
   * 강도 순서는 `1-2-3-4-5` > `2-3-4-5-6` > `(N-3)~N-1` > `(N-4)~N` > … > `3-4-5-6-7`이며, `numRank` 내림차순 상위 2개 값으로 예외 없이 정렬됩니다.
   * 완전 동숫자 스트레이트끼리는 **가장 높은 `numRank` 타일의 문양**을 비교합니다(`1-2-3-4-5`는 `2`의 문양, `5-6-7-8-9`는 `9`의 문양).
2. **플러시 숫자 우선 ([공식 가이드](https://www.didanonia.com/lexio))**: 문양이 아니라 5개 숫자의 `numRank`를 높은 순으로 1:1 비교하고, 5개 숫자가 모두 같을 때만 문양(`해 > 달 > 별 > 구름`)을 비교합니다.
3. **판정 우선순위**: 5장 판정 함수는 반드시 `스트레이트 플러시 → 포카드 → 풀하우스 → 플러시 → 스트레이트` 순으로 검사해야 하위 족보 오판정을 막을 수 있습니다.

## 3. 게임·라운드·턴 상태 머신

상태 전이는 `LOBBY → ROUND_START → TURN_ACTIVE → ROUND_SETTLEMENT → (ROUND_START | GAME_OVER)` 흐름을 따릅니다. 모든 턴 순환과 패스 카운트는 전체 방 인원이 아니라 **현재 라운드 생존자 리스트(`activePlayers`, 길이 $M$)** 기준으로 동작해야 합니다.

1. **라운드 시작 (`ROUND_START`)**:
   * 생존자 수 $M$에 맞는 타일 덱을 생성·셔플해 균등 배분합니다.
   * **선(Lead) 결정**: **`구름 3` 보유자**가 선입니다. 첫 턴에 `구름 3`을 반드시 포함해 내거나 공개할 의무는 없습니다([공식 FAQ](https://lexio.co.kr/bbs/board.php?bo_table=0111&wr_id=58)). (2인 옵션에서 `구름 3`이 제외된 경우, 배분된 타일 중 `(numRank, suitRank)` 최솟값 보유자가 선.)
   * 상태 초기화: `tableHand = null`, `lastPlayedBy = startPlayer`, `consecutivePasses = 0`, `currentTurn = startPlayer`.
2. **턴 진행 (`TURN_ACTIVE`)**:
   * **리드 상태 (`tableHand == null`)**: `PASS` 불가. 합법적인 1/2/3/5장 조합을 반드시 제출합니다.
   * **팔로우 상태 (`tableHand != null`)**:
     * `PLAY`: `tableHand`와 같은 장수이면서 비교 키가 더 큰 조합 제출 → `tableHand`, `lastPlayedBy` 갱신, `consecutivePasses = 0`.
     * `PASS`: `consecutivePasses += 1`. 패스하더라도 해당 트릭에서 영구 탈락하지 않으며, 다른 플레이어가 제출해 트릭이 이어지면 다음 자기 차례에 다시 낼 수 있습니다.
   * **턴 타임아웃 자동 처리 (확정)**:
     * 리드 상태 초과 시: 손패 중 `(numRank, suitRank)`가 가장 낮은 **싱글 1장** 자동 제출.
     * 팔로우 상태 초과 시: 자동 **`PASS`** 처리.
3. **트릭 초기화 (Trick Clear)**:
   * `consecutivePasses == M - 1`에 도달하면(마지막 제출자 본인 차례로 복귀) `tableHand = null`, `consecutivePasses = 0`으로 초기화하고 `lastPlayedBy`가 새로운 선이 됩니다.
4. **라운드 즉시 종료**:
   * 어떤 플레이어든 타일 제출 직후 `hand.length == 0`이 되면 즉시 `ROUND_SETTLEMENT`로 전환합니다.

## 4. 라운드 정산 및 공식 탈락제 파산 로직

정산은 현재 라운드 생존자(`activePlayers`)만 대상으로 진행합니다([2검사 FAQ](https://lexio.co.kr/bbs/board.php?bo_table=0111&wr_id=73), [칩 부족 FAQ](https://lexio.co.kr/bbs/board.php?bo_table=0111&wr_id=71)).

1. **'2' 검사 (유효 타일 수 산출)**:
   * 각 생존자 $i$의 남은 타일 수를 $R_i$, 그중 숫자 `2` 타일 개수를 $k_i$라 할 때,

     $$E_i = R_i \times 2^{k_i}$$

   * 1등은 $R_i = 0 \Rightarrow E_i = 0$.
2. **정산 순서 정렬 (결정론적 동점 처리)**:
   * 정렬 키: `(E_i 오름차순, R_i 오름차순, 해당 라운드 시작 기준 턴 순서 오름차순)`.
3. **순차 지불 및 즉시 OUT**:
   * 정렬된 1등부터 $M-1$등까지 순서대로 하위 등수에게서 차액(`E_payer - E_receiver`)을 수금합니다.
   * 상위 등수에게 지불하는 도중 보유 칩이 부족하거나 정확히 `0`이 되는 순간, **가진 칩까지만 지불하고 즉시 `isOut = true`(탈락)** 처리합니다.
   * 이미 `isOut = true`가 된 플레이어는 이후 하위 등수에게서 받을 점수가 남아 있더라도 **수금하지 못합니다**.
   * 탈락 시 `eliminatedRound = currentRound`, `eliminatedEffectiveTiles = E_i`를 기록해 최종 순위 산정에 사용합니다.

## 5. 다음 라운드 전환 및 최종 게임 종료 조건

정산 완료 후 다음 조건을 순서대로 검사합니다.

1. **탈락자 관전 전환**: 이번 라운드에 `isOut = true`가 된 플레이어는 `activePlayers`에서 제외되고 관전 모드로 전환됩니다(관전자는 테이블과 공개 정보만 수신).
2. **게임 종료 판정 (`GAME_OVER`)**:
   * 공식 3인 이상 기준: `currentRound == maxRounds(기본 5)` **또는** `activePlayers.length < 3`이면 즉시 게임 종료.
   * *(만약 2인전 옵션까지 허용한다면 `activePlayers.length < 2`일 때 종료.)*
   * 종료 조건에 해당하지 않으면 `currentRound += 1` 후 생존자 수 $M$에 맞춘 덱으로 `ROUND_START` 진입.
3. **최종 순위 산정**:
   * **생존자**: 최종 보유 칩 내림차순 (동점 시 마지막 라운드 $E_i$ 오름차순).
   * **탈락자**: 생존자 하위 순위로 배치하되, **늦게 탈락한 라운드 순**(같은 라운드 탈락자는 해당 라운드 $E_i$ 오름차순).

## 6. 서버 보안 및 동기화 원칙

* **정보 은닉**: 서버는 각 클라이언트에게 본인 손패만 전송하고, 타 플레이어 정보는 `remainingTileCount`, `chips`, `isOut`, `isConnected`만 브로드캐스트합니다.
* **서버 권위 검증(Authoritative Server)**: 클라이언트가 보낸 타일 제출 요청은 반드시 ① `currentTurn` 일치 여부, ② 실제 본인 손패 보유 여부, ③ 합법 족보 여부, ④ `tableHand` 대비 상위 조합 여부를 서버에서 재검증한 뒤 상태를 전이합니다.
